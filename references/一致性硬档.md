# 一致性硬档

> 这一份管的是「同一个角色，第十页和第一页还是同一个人」。
> 光靠一句「服装统一、画风统一」是拦不住的 —— 模型每次都在重新理解你的角色。
> 硬档的意思是：**把不能松的东西变成可以逐条核对的东西。**

---

## 一、脸三特征锚（治跨页脸漂移）

### 为什么不用发型做锚

发型是最不可靠的锚：
- 换个角度、换个风、戴个帽子，发型就变了
- 模型对「黑长直」这种描述的理解，每次都可能不一样
- 而且发型变了读者反而能接受（剧情里剪头发很正常），脸变了才要命

### 什么才是好锚

每个角色定 **3 个与发型无关、换个角度也认得出的特征**，分别落在三个部位：

| 部位 | 要写什么 | 反例（太泛） | 正例（能用） |
|---|---|---|---|
| **眼部** | 眼皮形状、眼角走向、瞳孔占位 | 「眼睛很大」 | 「上眼皮接近直线，眼尾微微下垂，眼白留得多」 |
| **眉毛** | 粗细、长度、与眼的距离、走向 | 「剑眉」 | 「眉骨低、眉尾平直不收尖，离眼很近」 |
| **脸型下段** | 颧骨、下颌、下巴、鼻的软硬 | 「瓜子脸」 | 「下颌偏方但转角软，下巴短而圆，鼻梁低平」 |

> 写的时候想一件事：**如果只能靠这三个部位的分辨率活下来，你还能在一张 2cm 大的格子里认出他吗？**

### 表情集：先立脸，再进正文

正式出页之前，先给每个主要角色跑一组基准图：

```
正面 / 四分之三侧 / 正侧 / 仰视 / 俯视
+ 六个必需表情：平静 · 惊讶 · 生气 · 难过 · 笑 · 无语
```

**这一步不能省。** 后果很实在：

- 你有了 11 张可复用的图，后面每一格都能指定「按表情集第 4 号来」
- 脸一旦定稿，后面 30 页都拿它当唯一锚（不是每次从真人照片重新翻译一次 —— 那是脸崩的头号原因）
- 角色多了也不会互相污染

### 写进锚定清单的格式

```markdown
【角色脸锚 · 陈序之】
- 眼部：上眼皮平直偏厚，眼尾略微下垂，瞳色近黑，高光只留一点
- 眉形：眉骨低，眉尾平直不收尖，与眼距离很近
- 下段：下颌线偏方但转角是软的，下巴短而圆，鼻梁低平
- 基准图：assets/陈序之-表情集.png（11 图合版）
- 本页表情：按表情集 03 号（压抑的惊讶），眉毛上抬幅度不超过半格
```

## 二、参考图角色声明（零成本，收益最大）

### 问题

一次喂 3 张参考图进去，模型会**自由发挥地乱抄**：
抄了身份图的姿势、抄了版式图的标注线、把场景图里的人物也画进来。

### 解法：每张图都声明「它只负责什么」

在提示词里，参考图不要裸喂，前面加一段编号声明：

```
INPUT IMAGES (in supplied order):
Image 1: identity. 陈序之的权威身份基准。只取可辨识的五官特征（眼皮形状、
         眉形、下颌轮廓），完全忽略这张图的姿势、表情、服装与构图。
Image 2: layout.   只提供格位、人物站位、脸部区域与气泡禁区。
         不要复制图上的编号、引导线、辅助标注。
Image 3: support.  只提供「雨天街道」这一条场景特征。
         不继承其中的任何人物、表演或构图。
Image 4: edit-target. 待修改的底图，改动要求优先于保留要求。
```

### 四种角色，各管一段

| 角色 | 只给什么 | 绝不能继承什么 |
|---|---|---|
| `identity` | 可辨识的五官结构 | 姿势、表情、服装、构图、背景 |
| `layout` | 格位、站位、脸区、气泡禁区 | 编号、引导线、灰框、说明文字 |
| `support` | 提示词里明确点名的那一条特征 | 人物、动作、构图、光源 |
| `edit-target` | 作为修改底图 | （改动要求优先） |

### 三条铁律

1. **顺序即编号**：喂图的顺序 = 声明里的 Image 1/2/3，绝不能错位
2. **一张图一个身份**：别让同一张图既当身份又当构图
3. **不多喂**：这一格用不上的图别塞，多一张就多一次污染机会

## 三、动作三时态表（治手崩、动作前倒、道具瞬移）

### 为什么需要

AI 画「他把戒指推过去」时，很容易画出：戒指既在手里又在柜台上、左手右手各一只、上一格拿着的杯子这一格凭空消失。

根因是：**提示词只描述了一个瞬间，没有告诉模型这个瞬间的前后。**

### 每格必填的五个字段

```jsonc
{
  "production": {
    "moment": "他把戒指推过柜台，指尖刚离开金属",
    "before": "戒指还在他掌心，左手半握，手肘撑在台面上",
    "after":  "戒指停在柜台边缘，他的右手悬在半空没有收回",
    "hands": {
      "陈序之": { "left": "扶着台面边缘", "right": "空手，指节还曲着" },
      "林晚":   { "left": "垂在身侧",     "right": "抬到一半，没敢碰" }
    },
    "props": [
      { "id": "ring", "before": "在陈序之掌心", "during": "被推出",
        "after": "停在柜台边缘", "heldBy": "陈序之.left" }
    ]
  }
}
```

### 三条硬校验（不通过就不许生图）

1. **持有对账**：`heldBy` 写成 `角色.左手/右手`，那只手的 `hands` 描述里必须出现这个道具 ID
2. **单手单物**：同一只手不能同时持有两样东西（除非明确写「夹在指间」之类）
3. **不许占位**：`moment / before / after` 里不许出现「待定」「TODO」「确定」「见前文」

### 一句口诀

> **画的是「一瞬」，写的是「三瞬」。**
> 上一瞬交代他从哪来，下一瞬交代他往哪去，模型才不会在这一瞬发明第三个手。

## 四、场次状态分层（画长篇必须）

### 三层结构

```
第一层 · 角色恒常    →  这个人的脸、体型、发色，全书不变
第二层 · 场次状态    →  这场戏在哪、几点、穿什么、桌上有什么
第三层 · 单格覆盖    →  只有这一格不一样（换装、回想、道具状态变化）
```

只有第一层是「永远」，第二三层都是「当前」。

### 为什么要分层

回想段落是最容易翻车的地方：
- 现在线：修表店 / 白天 / 围裙 / 桌上有一只待修的表
- 回想线：八年前 / 雨夜 / 校服 / 桌上空的

如果只有一份「当前状态」，回想就会把围裙和待修的表一起带进去。

分层之后：**回想 = 换一个场次，不是「在提示词里补一句这是回忆」。**

### 写法

```jsonc
{
  "场景库": {
    "修表店-现在": { "地点": "老城修表店", "时间": "午后", "陈序之服装": "深蓝围裙",
                     "道具": { "watch": "拆开的机芯摆在绒布上" } },
    "修表店-八年前": { "地点": "同一间店", "时间": "雨夜", "陈序之服装": "旧校服外套",
                       "道具": { "watch": "还在玻璃柜里，完好" } }
  },
  "单格": { "场次": "修表店-现在", "覆盖": { "陈序之服装": "换了礼装外套" } }
}
```

### 三个提醒

- **道具状态要写「当前值」而不是「动作」**：写「机芯摆在绒布上」，不写「他拆开了表」
- **同一场次内的变化也算变化**：从「拿着」到「放下」，是两格，不是一格
- **换装要写理由**：读者能接受换衣服，接受不了不知道为什么换

## 五、提交前的一致性核对清单

生图之前，逐条打勾。**有一条没过就不许出图。**

- [ ] 本页出现的每个角色，都有写好的脸三特征
- [ ] 每个角色的基准表情集已存在，且这一格指定了用哪个表情
- [ ] 参考图都写了角色声明（identity / layout / support / edit-target）
- [ ] 参考图顺序与声明编号一致，没有多喂用不上的图
- [ ] 每格的 `moment / before / after` 都写了，且不是占位词
- [ ] 每个可见人物的左右手都有描述
- [ ] 每个道具都有前/中/后状态和持有者，持有对账通过
- [ ] 回想/换装/时间跳跃的格子，场次已切换，不是靠嘴说
- [ ] 连续两格之间的人物左右没有无缘无故翻转（真要翻转，得有一格用来交代）
- [ ] 画风锚定、光源方向、色调三项全场统一，没有中途变卦

> 这十条不是形式主义。每一条都对应一种真实翻车：脸变了、手多了、道具丢了、读者懵了、风格跑了。
